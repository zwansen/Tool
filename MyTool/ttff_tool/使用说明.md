# TTFF 分析工具使用说明

针对 NMEA 日志的 **TTFF（Time To First Fix，首次定位时间）** 统计分析工具。
支持为 **每个日志文件独立配置复位标志**，自动识别复位事件、计算 TTFF，并生成带交互图表的 HTML 报告。

---

## 一、功能简介

- 按配置文件为每个文件**独立指定复位标志**（如 `$PSTMCOLD*1E`、`$KMDOK,KMDRST,h3F*4C` 等任意字符串），支持不同接收机/不同协议混合分析；
- 自动识别每个文件的复位事件，计算每次复位的 TTFF（复位时刻 → 首次有效定位时刻）；
- 输出各文件统计：复位次数、恢复次数/恢复率、TTFF 最小值 / 中位数 / 平均值 / P95 / 最大值；
- 生成**自包含**的交互式 HTML 报告（ECharts 已内嵌，离线双击即可打开），包含：
  - 各文件 TTFF 箱线图
  - 逐次复位 TTFF 序列图（可筛选文件、可切换散点图 / 点线图 / 折线图）
  - 各文件 TTFF 直方图（可切换文件）
  - 恢复率与平均 TTFF 对比图
  - 逐次复位明细表（复位行号、复位时刻、首次定位行号/时刻、TTFF、状态）
  - 全部图表支持**交互缩放**：滚轮/拖拽缩放 X、Y 轴，局部放大、还原、保存为图片
- 同时输出逐次复位明细 JSON，便于二次处理。

## 三、TTFF 统计方法（请先核对是否符合预期）

1. **复位事件识别**：日志中出现该文件配置的**复位标志行**，即视为一次复位。
2. **复位时刻 T_reset**：复位标志本身一般不含时间戳，取**复位标志行之前最后一条带有效时间戳的 RMC/GGA 语句**的时间（UTC，hhmmss.sss；日期取自 RMC 第 10 字段 DDMMYY，跨天按绝对秒处理）。误差不超过一个输出周期（0.1~0.2 s）。
3. **首次定位 T_fix**：复位后接收机须**先进入无定位状态**（出现 GGA 定位质量 = 0 或 RMC 状态 = V），之后出现的**第一条 GGA 定位质量 > 0** 的语句视为首次定位。
   > 这样可跳过复位命令写入后、接收机真正重启前短暂残留的旧定位（约 0.1~0.2 s），避免把复位前的旧定位误算为首次定位。
4. **TTFF = T_fix − T_reset**。
5. **未恢复定位**：某次复位之后、下一条复位标志出现前（或日志结束前）始终没有出现有效定位，该次复位记为"未恢复定位"，不参与 TTFF 统计。
6. **有效定位判据**：GGA 定位质量字段（第 7 字段）> 0（含 2D/3D 定位）。

## 四、配置文件说明

配置文件为 JSON，结构如下：

```json
{
  "settings": {
    "log_dir": "..",
    "output_html": "TTFF统计报告.html",
    "output_json": "ttff_results.json",
    "default_date": "040826"
  },
  "files": [
    {
      "file": "LG69T_NMEA.log",
      "reset_marker": "$PSTMCOLD*1E",
      "name": "LG69T",
      "note": "u-blox 冷启动命令"
    },
    {
      "file": "A8P-C00631CD40A00042-tongxian-NMEA-1.log",
      "reset_marker": "$KMDOK,KMDRST,h3F*4C",
      "name": "A8P-tongxian-1"
    }
  ]
}
```

### settings 字段

| 字段 | 必填 | 说明 | 默认值 |
|---|---|---|---|
| `log_dir` | 否 | 日志所在目录，相对运行目录；`file` 为相对此目录的路径 | `.`（当前目录） |
| `output_html` | 否 | 输出 HTML 报告文件名 | `TTFF统计报告.html` |
| `output_json` | 否 | 输出明细 JSON 文件名 | `ttff_results.json` |
| `default_date` | 否 | 日志中暂无 RMC 日期时的兜底日期（DDMMYY），RMC 有日期时自动更新 | `040826` |

### files[].字段（每个文件独立配置）

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 日志文件名（相对 `log_dir`）或绝对路径 |
| `reset_marker` | 是 | **该文件的复位标志**（在日志行中出现的字符串，按行匹配）。每个文件可配置不同值 |
| `name` | 否 | 报告中的显示名（短名）；缺省取文件名 |
| `note` | 否 | 备注，显示在报告总览表文件名下 |

> 提示：`reset_marker` 支持任意字符串，包括含逗号、`$`、`*` 的完整 NMEA 语句；按"该字符串是否在行中出现"匹配。

## 五、快速开始

### 环境要求

- Python 3.8+（无第三方依赖，仅用标准库）

### 运行

在项目根目录（或任意位置）执行。**以下命令是彼此独立的"可选用法"，任选一条即可完成一次完整分析，无需逐条执行**；参数也可以按需自由组合成一条命令。

```bash
# ① 最常用：使用默认配置（工具目录下的 ttff_config.json），日志在当前目录，输出到当前目录
python ttff_tool/ttff_analyzer.py

# ② 显式指定配置文件（与 ① 完全等价，仅当配置文件不在默认位置时才需要）
python ttff_tool/ttff_analyzer.py -c ttff_tool/ttff_config.json

# ③ 自定义输出文件名
python ttff_tool/ttff_analyzer.py -o report.html -j report.json

# ④ 日志不在配置的 log_dir 时，显式指定日志目录
python ttff_tool/ttff_analyzer.py --log-dir D:/logs/nmea

# ⑤ 组合示例：自定义配置 + 自定义输出 + 指定日志目录（一次执行）
python ttff_tool/ttff_analyzer.py -c my_config.json -o report.html -j report.json --log-dir D:/logs/nmea
```

运行后：
- 控制台打印每个文件的复位次数、恢复次数、恢复率、TTFF 中位数；
- 生成 `TTFF统计报告.html`（浏览器打开即可，图表已内嵌，无需联网）与 `ttff_results.json`。

### 命令行参数

| 参数 | 说明 | 默认值 |
|---|---|---|
| `-c, --config` | 配置文件路径 | `ttff_config.json`（cwd 下不存在时自动找脚本同目录） |
| `-o, --output-html` | 输出 HTML 报告路径 | 取配置 `settings.output_html` |
| `-j, --output-json` | 输出明细 JSON 路径 | 取配置 `settings.output_json` |
| `--log-dir` | 日志目录（覆盖配置） | 取配置 `settings.log_dir` |
| `-e, --echarts` | ECharts 库文件路径 | 脚本同目录 `echarts.min.js` |
| `--no-embed` | 不内嵌 ECharts，改用 CDN 外链（需联网） | 内嵌 |

## 六、输出说明

### TTFF统计报告.html

交互式报告，包含：

1. **TTFF 统计方法说明**（报告中可随时复核）；
2. **各文件统计结果总览表**：复位标志、复位次数、恢复次数/恢复率、TTFF 五档统计、结论；
3. **图 1 箱线图**：有有效样本文件的 TTFF 分布（最小 / 四分位 / 中位 / 最大）；
4. **图 2 逐次复位 TTFF 序列图**：点击文件名标签可多选/取消文件；"绘图类型"可切换散点图 / 点线图 / 折线图；悬停显示复位时刻与首次定位时刻；
5. **图 3 直方图**：切换文件查看 TTFF 分布形态；
6. **图 4**：恢复率条形图 + 平均 TTFF 对比图；
7. **逐次复位明细表**：每次复位的序号、复位标志行号、复位时刻、首次定位行号/时刻、TTFF、状态（已恢复 / 未恢复）。

**交互缩放操作**（图 2 / 图 3 支持按轴缩放；其余图表支持框选/还原/保存）：

- **滚轮缩放按鼠标位置自动选轴**：
  - 鼠标停在 **Y 轴（左侧刻度/轴线）** 上滚动 → **只缩放 Y 轴**
  - 鼠标停在 **X 轴或绘图区** 内滚动 → **只缩放 X 轴**
- **左键拖拽**：平移视图（X、Y 均可平移，视图跟随鼠标移动，类似地图操作；放大后便于观察任意区域）
- **底部滑条**（图 2 / 图 3）：拖动左右滑块快速定位区间
- **右上角工具箱**：`框选缩放`（按住左键框选局部区域放大）、`还原`（恢复原始视图）、`保存图片`（导出 PNG）
- **图表放大**：每个图标题右侧都有 `⛶ 放大` 按钮，点击后弹出大尺寸浮层（包含工具箱、滑条、按轴缩放、拖拽平移、Esc 关闭），便于仔细查看

### ttff_results.json

```json
{
  "A8P-C00631CD40A00042-tongxian-NMEA-1.log": {
    "summary": { "n_resets": 264, "n_ok": 0, "n_nofix": 264, "recovery_rate": 0.0 },
    "cycles": [
      {
        "reset_line": 353703,
        "reset_time": 18620334.1,
        "fix_line": null,
        "fix_time": null,
        "ttff": null,
        "status": "no-fix"
      }
    ]
  }
}
```

- `reset_time` / `fix_time`：距 2026-01-01 的绝对秒数（便于跨天计算）；
- `status`：`ok`（已恢复，含 ttff 值）/ `no-fix`（未恢复定位，ttff 为 null）。

## 七、常见问题

**Q1：报告图表不显示？**
报告已内嵌 ECharts，正常离线打开即可。若仍不显示，请确认浏览器允许本地 JavaScript；或重新用 `--no-embed` 生成（需联网加载 CDN）。

**Q2：不同接收机使用不同复位标志怎么办？**
在配置文件中为每个文件分别填写 `reset_marker` 即可，互不影响。

**Q3：某文件复位后一直没定位，报告里 TTFF 全是"—"？**
说明该日志中复位后始终未出现 GGA 定位质量 > 0 的语句（接收机未恢复定位，或日志在恢复前结束）。请检查测试环境 / 复位指令，或延长日志记录时长。

**Q4：日志跨午夜（日期切换）会算错吗？**
不会。日期取自 RMC 第 10 字段（DDMMYY），统一换算为绝对秒后做差，跨天自动正确。

**Q5：想调整"首次定位"的判据（比如只算 3D 定位）？**
修改 `ttff_analyzer.py` 中 `analyze_file()` 的 GGA 定位质量判断逻辑即可（当前为 `q > 0`）。

**Q6：没有 echarts.min.js 怎么办？**
从 https://registry.npmmirror.com/echarts/ 下载对应版本放到工具目录，或使用 `--no-embed` 外链 CDN。
