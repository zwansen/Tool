# BPDEBUG 钟漂变化分析与通用解析框架 — 使用与功能说明

> 适用对象：GNSS 工具箱（MyTool）中的「钟漂变化分析」功能，以及其底层 `bpdebug_framework` 通用 BPDEBUG 解析框架。

---

## 1. 功能概述

### 1.1 钟漂变化分析（工具箱 UI 功能）

解析 BPDEBUG 日志中的 **CNRCV** 语句，提取三个钟漂值随时间变化的曲线，支持多文件叠加对比、可选温度曲线，输出交互式 HTML 报告。

| 参数                 | 说明                   |
| ------------------ | -------------------- |
| **flashclkdrifft** | 闪存钟漂（CNRCV 第 11 字段）  |
| **curclkdrifft**   | 当前钟漂（CNRCV 第 12 字段）  |
| **recvclkdrifft**  | 接收机钟漂（CNRCV 第 13 字段） |

### 1.2 BPDEBUG 通用解析框架（bpdebug_framework）

BPDEBUG 数据解析中，**按 `$CHEND` 切分历元 + 提取 UTC 时间 + 跨天检测 + 不定位历元 10Hz 打点** 是所有分析共用的基础步骤。该框架把这部分固化为可复用层，之后分析**任意语句、任意字段**只需声明「语句前缀 + 字段索引 + 解析方式」，无需重复描述历元逻辑。

---

## 2. 历元解析基础（框架自动处理）

所有基于该框架的分析，以下逻辑**自动完成**，无需关心：

1. **历元切分**：以 `$CHEND` 语句为每个历元的结束标志。
2. **历元时间**：优先取历元内 `$GNRMC` / `$GNGGA` 语句的时间字段（UTC `HHMMSS.mmm`）。
3. **日期维护（跨天）**：`$GNRMC` 的第 9 字段（`DDMMYY`）维护当前 UTC 日期；若时间回绕超过 12 小时视为跨天（+1 天）。
4. **不定位历元**：历元内无有效 GGA/RMC 时间时标记为 `is_nofix=1`，时间从最近有效历元按 **10Hz（0.1 秒/历元）** 打点补充；无任何参考时间的历元 `utc_time=None`。
5. **损坏语句防护**：时间字段严格校验 `^\d{6}(\.\d+)?$` 且 `h<24, m<60, s<60`，乱码时间（如 `210333939202`）不会造成日期跳变。

## 3. 钟漂变化分析（工具箱 UI）使用说明

### 3.1 入口

启动工具箱（`启动工具箱.pyw`）→ 左侧导航「质量分析」→ **「钟漂变化分析 📉」**。

### 3.2 输入配置

| 控件           | 说明                                 |
| ------------ | ---------------------------------- |
| **添加文件…**    | 多选 BPDEBUG 日志（.log / .txt / .nmea） |
| **添加文件夹…**   | 自动纳入文件夹下所有日志文件                     |
| **＋ 添加输入文件** | 手动新增空文件行                           |
| 文件卡片「显示名称」   | 报告中的显示名（缺省取文件名）                    |
| 文件卡片「备注」     | 可选，显示在图例中，如「接收机A(常温)」              |

### 3.3 参数设置

| 参数             | 说明                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| **温度 CSV（可选）** | 温度文件路径。格式：第 2 列为北京时间 `YYYY/M/D H:M:S`，第 4 列为 T1。**留空 = 恒温测试**，不绘制温度曲线，但保留坐标轴（三个钟漂图自动均分高度）；填写后为 4 图模式（温度 + 三钟漂） |
| **报告标题**       | 自定义报告页面的标题文字                                                                                                   |
| **报告文件名**      | 自定义输出的 HTML 文件名（自动补 .html）                                                                                     |
| **输出目录**       | 留空默认输出到 `output/clock_drift/`                                                                                  |

### 3.4 运行

点击「运行」→ 日志窗口显示解析进度 → 完成后自动弹出「结果预览」（内嵌渲染 HTML 报告），也可点「在浏览器中打开」全屏查看。

### 3.5 报告交互

| 操作           | 效果                            |
| ------------ | ----------------------------- |
| 滚轮           | 缩放 X 轴（时间轴）                   |
| Ctrl + 滚轮    | 缩放 Y 轴                        |
| 鼠标左键拖动       | 平移 X 轴                        |
| Ctrl + 拖动    | 平移 Y 轴                        |
| 底部滑块         | 缩放 / 平移 X 轴                   |
| 每个图右侧垂直滑块    | 缩放 / 平移 Y 轴                   |
| 工具栏框选放大      | 拖拽框选矩形区域放大                    |
| 工具栏还原        | 恢复默认视图                        |
| 悬停           | 显示该时刻所有文件的三个钟漂值（+温度）          |
| 图例点击         | 隐藏 / 显示对应曲线                   |
| 文件按钮勾选       | 叠加 / 隐藏某个文件                   |
| **显示不定位点开关** | 默认关闭（大量不定位散点会卡顿）；勾选后显示全部不定位历元 |

### 3.6 输出产物

输出目录（默认 `output/clock_drift/`）包含：

| 文件                          | 说明                           |
| --------------------------- | ---------------------------- |
| `钟漂变化分析报告.html`（或自定义名）      | 交互式 HTML 报告                  |
| `data_f1.js` … `data_fN.js` | 各输入文件的数据（全量 tooltip + 降采样绘图） |
| `data_temp.js`              | 温度数据（仅填写温度 CSV 时生成）          |
| `echarts.min.js`            | ECharts 库（自动拷贝）              |

## 4. 注意事项

- BPDEBUG 日志文件通常较大（10~14 GB），解析约需 3~4 分钟/文件，属正常现象。
- 不定位历元较多（TTFF 测试可达 6~8 万/文件）时，报告默认关闭不定位散点以保证流畅；需要时勾选「显示不定位点」。
- 温度 CSV 时间列为**北京时间**，框架自动转换为 UTC（-8 小时）。
- 若报告内嵌预览不可用（缺少 QtWebEngine），可点「在浏览器中打开」用系统浏览器查看。
